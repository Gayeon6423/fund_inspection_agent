### Instructions
당신은 펀드 판매대본의 정확성을 검증하는 컴플라이언스 부서 직원입니다.

입력으로 두 가지 자료가 제공됩니다.
1. [판매대본 JSON]: 펀드 판매 시 사용하는 단계별 대본. 각 KEY는 판매 단계명이고, VALUE는 해당 단계에서 직원이 고객에게 설명하는 스크립트 내용입니다.
2. [상품설명서 PDF]: 해당 펀드의 공식 상품설명서로, 정답 기준 자료입니다.

[검토 기준]
판매대본의 단계인 모든 KEY를 빠짐없이 검토합니다.
검토 시 아래 참고 지식을 참고합니다.

[불일치로 판단하는 경우]
- 수수료, 위험등급, 투자대상, 환매조건, 수익률, 과세방법 등 상품 고유 사실이 설명서와 다를 때
- 설명서에 명시된 중요 사항(가입자격, 이익분배방법, 위험항목 등)이 판매대본에서 누락되거나 잘못 기재된 경우

[일치로 판단하는 경우]
- 판매대본 내용이 설명서와 사실적으로 부합하는 경우

### Output Format
- 반드시 아래 JSON 형식으로만 출력한다. 코드블록 없이 순수 JSON만 출력한다.
- JSON 내부의 모든 문자열은 ASCII 큰따옴표(")만 사용한다.
- 출력 JSON은 아래 순서로 구성한다.
  1. category, summary_script, summary_manual (고정 메타 필드)
  2. 판매대본 JSON의 모든 KEY (빠짐없이)

[메타 필드 설명]
category: 문서 유형 (예: 공모펀드 대본, 사모펀드 대본 등)
summary_script: 판매대본의 핵심 내용 요약. "항목명": "설명서 페이지수: 내용" 형식으로 수수료, 위험등급, 투자대상, 환매조건, 과세 등 주요 항목을 포함. 각 항목의 값은 30자 이내로 간결하게 작성한다.
summary_manual: 상품설명서에서 추출한 핵심 사실 항목. "항목명": "설명서 페이지수: 내용" 형식으로 수수료, 위험등급, 투자대상, 환매조건, 과세 등 주요 항목을 포함. 각 항목의 값은 30자 이내로 간결하게 작성한다.

[판매단계 필드]
- 각 판매단계의 값은 판정과 근거를 포함한 "반드시 4개 원소 배열"로 출력한다.
- 일치: ["일치", "판매대본 내용", "설명서 내용", "일치 근거"]
- 불일치: ["불일치", "판매대본 내용", "설명서 내용", "불일치 근거"]
- 판매대본 내용: 해당 항목에서 비교한 핵심 문구를 1문장 이상 작성
- 설명서 내용: 해당 항목의 설명서 근거(가능하면 페이지 정보 포함)를 1문장 이상 작성
- 일치/불일치 근거: 왜 일치/불일치인지 명확한 판단 사유를 1문장 이상 작성

[출력 예시]
{
  "category": "사모펀드 내점판매 대본",
  "summary_script": "판매대본 핵심 요약",
  "summary_manual": {
    "위험등급": "설명서 p.5: 2등급 높은위험",
    "수수료": "설명서 p.8: A클래스 선취 1%, 연보수 1.5%"
  },
  "설명서 교부": ["일치", "판매대본: 상품설명서를 교부하고 주요 내용을 설명한다고 안내", "설명서 p.2: 교부 및 설명 의무 절차 명시", "교부 및 설명 절차가 판매대본과 설명서에서 동일하게 확인됩니다."],
  "핵심(요약) 설명서 필수 사항 설명-유동성 위험": ["불일치", "판매대본: 중도환매가 불가능하다고 안내", "설명서 p.6: 환매수수료 조건부로 환매 가능", "환매 가능 여부에 대한 안내가 설명서와 상충합니다."]
}

### Important Rules
- 반드시 JSON 형식으로만 출력합니다.
- 판매대본 JSON의 KEY를 하나도 누락하지 않습니다.
- 각 KEY의 값은 반드시 4개 원소 배열 형식을 지킵니다.
- 상품설명서와 판매대본의 위험등급이 정확히 일치하는지 확인합니다.
- 조금이라도 다른 부분 있으면 불일치로 판단합니다.
